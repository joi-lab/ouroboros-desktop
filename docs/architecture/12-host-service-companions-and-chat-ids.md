# 12. Host Service, Companion Processes, and Chat IDs

Connectors report events and typed facts; the host validates and captures them, then decides attention from authored wakes and execution conditions. This chapter maps Host Service, delivery and companions. Silent may wake; Paused hears without a new focus. Chat ids include a hidden destination. Reviewed owner-bound transports are control surfaces; external speech is not owner authority, and unknown outcomes authorize no repeat.

### Host Service boundary

`ouroboros/gateway/host_service.py` listens on `OUROBOROS_HOST_SERVICE_PORT` (routes/grants: §4). Every request authenticates an opaque `x-skill-token` bound to payload hash, executable review, enablement and grants. Tokens contain no secrets, refuse stringification and stale on edit (`skill_token.py`). `POST /notify` (`host_notify.py`, `notify_owner` grant, `notify_version` on `/identity`) writes one sentence up to `NOTIFY_TEXT_MAX_CHARS` as a `skill_notice` System row signed `Notice · <skill>`, without waking a model; 503 means unconfirmed. Transport review covers identity, attribution, polling bounds, Panic cleanup, token confinement and exfiltration. Reviewed owner-bound transports can control Ouroboros; slash commands require a separate positive-identity owner slot (`supervisor/state.py`), preventing unknown binding and web lockout of the remote owner. `wait_for_response` is A2A-only.

Shared decision and language writers: §4 Server API Endpoints. Review-operation waits reach their exact live controller after author completion through the canonical `pending_action`; a stale revision or identity, or no consumer, is 409 (§6 Quota and auth waits). A review verdict grants no continuation or additional skill authority.

Admission is one limiter with two policies (`host_service._RateLimiter`): the WS relay lane (`/ui/ws-message`) is a token bucket, so a burst does not silence a widget for the rest of a minute, and every other lane keeps the sliding window. Refused relays aggregate per burst into one durable `host_service_ws_relay_dropped` row in `logs/events.jsonl` with the dropped count; the child's `send_ws_message` stays best-effort `None`, and the in-process broadcast path has no bound.

Chat uploads have one storage owner, `chat_uploads.store_upload`, for Host-confined paths and completed multipart spools: the Host Service calls it directly, the browser's `/api/chat/upload` through the `gateway.files` facade. The request's worker both copies and closes its spool, so HTTP cancellation cannot interrupt cleanup; the skill keeps its source. Neither ingress rejects a file for size; the Host's request count bound (`_INJECT_ATTACHMENT_MAX`) and the Files-browser upload policy keep their own contracts. Host attachment copies share one request-local cleanup stack: a partial copy, refusal or cancellation removes only new unaccepted copies, a replay never adopts duplicates, and accepted bytes survive disconnects and unknown write outcomes, which claim no acceptance.

### Operation correlation

Named injection returns `operation_ref=<chat_id>:<client_message_id>` on 200/202/504 and disconnect. `supervisor.message_ingress.accept_local_message` resolves raw `reply_to` before writing the canonical `log_chat` row, then queues work. Same-id/text/skill retries rejoin even before dequeue; changed content, source or Reply address yields 409. `chat_uploads.same_message` compares ordered attachment `[sha256, name]` pairs, allowing regenerated stored names. Inline photos are bounded before decode (`_INLINE_IMAGE_MAX`; CREATING_SKILLS `inject_chat`), retained in `data/uploads` and staged; non-image bytes become files, never pixels by label alone.

The in-memory queue can lose accepted delivery on crash (`lost`, no second enqueue). A same-id retry after this process's canonical write raised hands over the row (`queued`). Routing annotations and outbound task ids grant no access: reads, named response waits and cancellation bind the record's complete `origin_message_ref` to the authenticated skill's source; `DirectActivityRegistry` carries it too. Waits read that operation's retry-aware result, not chat order. Cancel also requires the same installation, then uses §5's durable intent/cascade custody; otherwise `cancel_unsupported` precedes any intent. Unresolved custody never means `cancelled`.

### Focus in places

`review_requested` and `assigned` are observed wake facts, never inferred from words. Source-bound roots use `send_user_message(destination="main", request_id=...)` and `escalate(..., request_id=...)` for private Main contact. `presence_owner_contact.py` retains typed source facts; the voice line renders them, preserving authored words. Messages use the outbox; `owner_quiz` owns questions. Deferred events use the attached supervisor bus. Identical retries rejoin; changed fields, including waiting intent, refuse. Only source-bound contact deduplicates omitted keys. Authority-only roots keep ordinary room questions. Delegated children report upward.

Live answers share the author's final-drain admission lock. Late answers use ordinary Main intake with exact owner words, the source snapshot and current child reference. The owner stays unrestricted; only roots it starts inherit `presence_binding_authority`, never an automatic external final. External facts confer no owner authority. Silent permits private contact; Paused admits no new focus and preserves owed contact. Service notices and scheduled notes keep separate gates. Display routing: §3.

`GET /identity` advertises independent `presence_main_contact_version: 1`, `presence_work_output_version: 1` and `presence_wake_facts`. Earlier place/continuation/delivery versions imply none of these; a required missing fact is a setup gap, never a fallback through owner ingress.

`POST /presence/turn` (`presence_runner.py`) admits exact provider/account/conversation/thread facts, skill-confined files and an authenticated place. Conversation and active-turn leases span processes; HTTP disconnect releases neither work nor capacity. Live retries join only matching conversation/actor/text under the turn ID; mismatch is `presence_event_identity_conflict` (409), never another room's answer. Refusals: CREATING_SKILLS "Places and focus transport ingress".

Unknown outcomes never authorize event replay. Before effects, the runner writes and reads its source-bound RUNNING row/controller; ambiguous writes allow receipt retry, not regeneration. Lost stacks, unknown terminals and cancellation return retained refusals: transports retain event/receipt, release input FIFO and observe original/child separately. `/presence/work` remains pending while the attempt can change (`presence_recovery.attempt_ended`), then serves canonical selected speech or failed/cancelled silent with unknown-effect facts. The orphan sweep records failed/`presence_attempt_lost`; `presence_recovery.py` retains `host_task_facts` for room memory/consciousness without forced questions or apologies. Missing evidence proves neither silence nor no effect.

Only `presence_retry_proof` permits regeneration: first-round temporary refusal, every route engine-confirmed `not_started` and ledger-released, no response/tool/handoff, and a dated reset. After reset the conversation gate writes `presence_retry_next`, a new physical ID under the original event; other refusals remain retained. A live turn's shared fallback/continuation (§6) keeps earlier effects, unknown cost, controls and its conversation through recovery or retained refusal, never replaying the event.

`/presence/work` keeps queried `work_ref`, producer `task_id`, canonical `output_ref` and actual `child_work_ref` distinct. Consumers observe original, child and continuation outputs independently, including selected failed-terminal output, deduplicating by output identity, never text or polled work. Missing legacy identities stay missing (`test_presence_connector_contract.py`).

`presence_continuation.py` parks only for the author's left review (commit/change/result, `review_pause`) or required private Main question. It grants no generic sleep, detach, owner Pause or budget-pause callback. With tool, process and service custody idle, it records `open_turns` and a source-bound write-once initial envelope on the RUNNING task, reads them back, publishes the envelope, then lends conversation and active slot. Otherwise it waits holding custody. Reentry reacquires both in admission order before any model/tool/forced call and appends `[PRESENCE CONVERSATION RESUMED]` facts. Hard stops use the zero-call rail; rounds and wallet persist. Bound question waits resume without inventing consent; durable terminal rows reconcile questions and waits, including cancellations, while unknown attempts remain unconfirmed. Wait-ended events address the question's publication room.

Only `continuation_version: 1` consumers take the initial envelope; others await terminal. Reviews publish nothing themselves, released selections are never resent, and lost authors stay interrupted without automatic restart. An explicit new event can start a new author from retained facts. Wire: CREATING_SKILLS "Presence continuation".

Reentry retains exact rows and gaps in immutable `presence_reentry` artifacts, read through existing task scope with `get_task_result(task_id, presence_reentry_sha256, …)` and `presence_reentry_offset`. It reads only the producer's conversation from `state/dialog.sqlite` within frozen bounds. Legacy cursors use the import ledger; new snapshots bind the end to a retained row identity. Inode/mtime-only snapshots report `legacy_source_identity_unavailable`, keeping their text; import gaps remain explicit (§6). `presence_observations.py` accepts transport-queue snapshots in `event.conversation.transport_queue` or authenticated work POSTs: dated observations, never inbox certainty, admission or delivery proof; absent means unknown.

Entry/receipt identity uses `presence_bindings.conversation_key` (empty thread `0`). Durable `first_lent_at` anchors parks/termination; returning authors update their own `open_turns` entry without replacing newer pointers. Outcomes: `message`, `silent`, `tool_delivered`, `deferred` (requires admission; orphaned children replay silent). `peer_roster.independent_message_target` admits `forward_to_worker` to source-bound RUNNING turns as peer context, never owner authority. Proactive speech uses connector tools.

`places.py` owns atomic revisioned `state/places.json`, shared by `ouroboros/gateway/places_api.py` and `configure_presence`. `places_migration.py` copies legacy bindings/instructions/topics/model/folder once, retaining source files and route identities. Only owner-door turns/authenticated owner APIs confirm owner accounts; connector updates cannot overwrite owner/mind choices.

`ouroboros/gateway/host_service_places.py` captures source events/attachments before admission. Paused, Off/Panic and unmatched events settle heard/silent; exhausted or unknown allowance requests retry. `conversation_lease.py` owns process/file locks, lending and reacquisition. Only an accepting local author with a held conversation lease receives `place_event` context-only mail, under its final-drain admission lock; a closed, ended or remote author leaves ordinary admission eligible. Accepted final-drain context earns a round, never owner authority. Stop finds remote lent authors by stack-lifetime locks; reentry checks `supervisor.consciousness_carriers.autonomous_work_enabled` before reacquiring, ending on the zero-call rail if disabled. Focus keeps consciousness provenance/autonomy and a root cost ceiling; no new capability ceiling is added, and legacy ceilings remain decodable.

`presence_context.py` appends `prompts/FOCUS.md` after the shared prefix: actor/wake facts, authored notes, existing work, allowance, roots and folder address; full knowledge topics remain context. `finish_task` selects speech or silence. `place_reply.py` checks current Place state and Safety (`place_reply`) before automatic speech, including promoted roots with a retained destination but no wake stamp. Flags return to the mind; Silent/Paused/disconnected/Advises holds become one System row per task/reply subject. Forced finals cannot bypass an unresolved flag. Cached turns, continuation envelopes and polls recheck state without generation or another Safety call; outward silence retains durable answer/output identity. Late receipts remain evidence with warnings. Existing transport custody and recovered-output identities persist.

Receipt mode is negotiated per turn (CREATING_SKILLS "Reporting actual Presence delivery"). `presence_delivery.py` accepts authenticated `/presence/delivery` observations through the chat writer: mode 1 logs outgoing speech on provider receipt, mode 0 logs delivery-unconfirmed authorship. Typed `presence_delivery` never finalizes a task; failures/uncertainty are System facts. Receipts prove writing, not reading. Identical readable reports deduplicate; conflicts refuse. Malformed retained rows yield `history_coverage=gapped`, where `duplicate=false` means only no readable match. Transport outboxes own reporting backoff; report failure neither resends nor blocks provider delivery. Deterministic client-id lookup in `state/dialog.sqlite` survives Host restart and refuses unknown import coverage.

### Companion processes

Reviewed manifest descriptors enter host-supervised durable custody: reconcile after lifecycle changes/restart; stop on disable, unload or panic. Workers adopt the server's live set from `state/extension_generation.json` at task start or a dispatch miss, without waiting for pool respawn. Worker changes request reconciliation through `state/extension_reconcile/`, never spawn server children. Each result names its observing process. Server health is authoritative; worker evidence qualifies it, and failed handoff cannot advance `last_known_good`. Exhausted restart budgets retain their terminal reason until a successful start. The reviewed payload is the companion's cwd; edits stale review before reload. `state/extension_companions.json` projects live state (§13).

### Chat-id delivery

Each message has exactly ONE destination. Chat IDs are values; absence is `None` (§11.1 `chat_id_policy`). `HIDDEN_CHAT_ID` (0) is the real hidden destination for Skill Review and unbound headless work, with no browser reader. `message_bus.notification_chat_route` decides where a notice goes; a `chat_id=0` history query coerces to Main, excluding chat-0 rows. A lineage binding or the task's admitted Project chat brings them to a Project; negative A2A ids never enter human streams. An exhausted terminal outbox notice skips chat 0 (no reader) while the durable incident and saved message remain; only positive same-id, same-destination evidence suppresses that notice (`terminal_delivery`), never a bare delivered id or a missing ACK. Memory and consolidation provenance follows the same value/`None` policy: a per-window registry snapshot names Main and the current Projects with stable chat ids, missing or ambiguous values stay explicit and never default to Main, and a presence room is named only by transport facts that re-derive its chat id. These labels are read-only source attribution and alter no routing, visibility or delivery state.

Place owners: `place_intake.py` decides attention; `place_arrivals.py` owns heard decisions, deferred source blobs and room/activity indexes; `place_projection.py` projects owner summaries. Gateway intake/lookup/receipts live above. `loop_completion_schema.py` selects completion while preserving live legacy registries; `tool_effects.py` and `place_guard.py` own declared effects/targets (§13).

Heard-only events create no task/context blob: the accepted room row retains identity and final reason (`paused`, `off`, `no_wake_match`, current-author handoff); later On never reconsiders it. Focus start and heard settlement share the intake lock, preserving admitted custody. Source rows stay immutable; `dialogue_store` derives deferred focus-source pointers from existing dedup records, and `chat_chain.source_row_id` preserves their identity.

`places.place_room_index` reads latest arrivals and nonterminal focus counts through indexes, without historical walks or per-arrival document loads. Unknown task-store counts stay null. Only the owner's rooms endpoint requests arrival details, decoded after the transaction; polls stay index-only. Discovery may miss legacy/outgoing-only rooms; import/gap flags describe the store, not provider completeness. Indexes build once from source rows. `ouroboros/gateway/place_history.py` projects recorded delivery/heard facts, exact-task focus starts and current owner confirmation (CLIENT_CONTRACT “Places”). `account_candidates` suggests up to 20 nonbots from the newest 50 arrivals, without identity confirmation or another actor list. Migration imports valid neighbors, records bad bindings in `migration.problems` and publishes one marker; `/api/places` exposes `migration_problems`.

For an opaque outbox mutation (empty conversation id), `GET /presence/place` reports any Silent/Paused place owned by that authenticated connector/provider/account, including broad and migrated wildcard accounts. An optional `thread_id` resolves a topic-specific place; omission keeps the room lookup. Declared tool destinations match account, conversation and thread as separate facts, and each recipient is checked independently. Retained-work GET/POST may omit `binding_id`; authentication checks the retained task's connector, never the ref alone. POST accepts exactly `transport_queue` plus an optional `binding_id`; legacy binding ids remain checked.
