# 12. Host Service, Companion Processes, and Chat IDs

Three rules govern places:
- Facts are typed by the connector; judgment belongs to the mind. Core matches membership, never message text.
- Identity describes the credential; the owner's existing account confirmation says whose it is.
- New identity facts ride status, events and task/room payloads, never new `places.json` fields.
Silent can wake; Paused admits no new focus. Unverified speech grants no owner authority; unknown outcomes authorize no repeat.

### Host Service boundary

The Host Service (`ouroboros/gateway/host_service.py`, `OUROBOROS_HOST_SERVICE_PORT`) authenticates `x-skill-token` against payload hash, executable review, enablement and grants. Tokens hold no secrets, stale on edits and refuse stringification (`skill_token.py`); routes/permissions: §4. `POST /notify` (`host_notify.py`, `notify_owner` grant, `/identity.notify_version`) writes one sentence ≤`NOTIFY_TEXT_MAX_CHARS` as a `skill_notice` System row signed `Notice · <skill>` in the owner's chat, waking no model; 503 means unconfirmed. Review covers transport identity/attribution, bounded polling, panic cleanup, token confinement and exfiltration. Reviewed owner-bound transports may control Ouroboros; external slash commands use a separate positive-owner slot (`supervisor/state.py`): unidentified transports cannot bind, web identity cannot exclude the remote owner. `wait_for_response` is A2A-only.

Decision/language writers: §4. Review waits reach their live controller after author completion via `pending_action`; a stale revision/identity or absent consumer is 409 (§6 Quota and auth waits). A verdict grants no continuation or skill authority.

`host_service._RateLimiter` is a token bucket for `/ui/ws-message` bursts and sliding windows elsewhere. Refused relays aggregate per burst as `host_service_ws_relay_dropped` with count in `logs/events.jsonl`; child `send_ws_message` stays best-effort `None`, in-process broadcast unbounded.

`chat_uploads.store_upload` owns Host-confined paths/completed multipart spools, called directly by Host Service and through `gateway.files` for `/api/chat/upload`. The worker copies and closes its spool despite HTTP cancellation; skills keep sources. Neither ingress rejects size; `_INJECT_ATTACHMENT_MAX` and Files-upload policy remain separate. One request-local cleanup stack removes new unaccepted copies on partial copy/refusal/cancellation; replay adopts no duplicates. Accepted bytes survive disconnect/unknown outcomes, which claim no acceptance.

### Operation correlation

Named injection returns `operation_ref=<chat_id>:<client_message_id>` on 200/202/504 and disconnect. `supervisor.message_ingress.accept_local_message` resolves raw `reply_to` before writing the canonical `log_chat` row, then queues work. Same-id/text/skill retries rejoin even before dequeue; changed content, source or Reply address yields 409. `chat_uploads.same_message` compares ordered attachment `[sha256, name]` pairs, allowing regenerated stored names. Inline photos are bounded before decode (`_INLINE_IMAGE_MAX`; CREATING_SKILLS `inject_chat`), retained in `data/uploads` and staged; non-image bytes become files, never pixels by label alone.

The in-memory queue can lose accepted delivery on crash (`lost`, no second enqueue). A same-id retry after this process's canonical write raised hands over the row (`queued`). Routing annotations and outbound task ids grant no access: reads, named response waits and cancellation bind the record's complete `origin_message_ref` to the authenticated skill's source; `DirectActivityRegistry` carries it too. Waits read that operation's retry-aware result, not chat order. Cancel also requires the same installation, then uses §5's durable intent/cascade custody; otherwise `cancel_unsupported` precedes any intent. Unresolved custody never means `cancelled`.

### Focus in places

`review_requested`/`assigned` are observed facts, never inferred words. Source-bound roots contact Main with `send_user_message(destination="main", request_id=...)` or `escalate(..., request_id=...)`. `presence_owner_contact.py` retains source facts for the voice line, preserving authored words. Messages use the outbox, questions `owner_quiz`, deferred events the attached supervisor bus. Identical retries rejoin; changed fields (waiting intent included) refuse. Only source-bound contact deduplicates omitted keys. Authority-only roots keep room questions; children report upward.

Live answers use the author's final-drain admission lock; late answers enter Main with the exact owner words, source snapshot and child reference. Only owner-started roots inherit `presence_binding_authority`, never an automatic external final; the owner stays unrestricted. Silent permits private contact; Paused preserves owed contact without new focus. Service/scheduled notices keep separate gates. Display routing: §3.

`/identity` independently advertises `presence_main_contact_version: 1`, `presence_work_output_version: 1` and `presence_wake_facts`; earlier place/continuation/delivery versions imply none. Missing required support is a setup gap, never fallback through owner ingress.

`POST /presence/turn` (`presence_runner.py`) admits exact provider/account/conversation/thread facts, skill-confined files and an authenticated place. Conversation and active-turn leases span processes; HTTP disconnect releases neither work nor capacity. Live retries join only matching conversation/actor/text under the turn ID; mismatch is `presence_event_identity_conflict` (409), never another room's answer. Refusals: CREATING_SKILLS "Places and focus transport ingress".

Before effects, the runner writes/reads its source-bound RUNNING row/controller; ambiguous writes permit receipt retry, never regeneration. Lost stacks, unknown terminals and cancellation return retained refusals: transports keep event/receipt, release FIFO and observe original/child separately. `/presence/work` stays pending while the attempt can change (`presence_recovery.attempt_ended`), then serves selected speech or failed/cancelled silence with unknown-effect facts. The orphan sweep records failed/`presence_attempt_lost`; `presence_recovery.py` keeps `host_task_facts` for memory/consciousness without forced questions/apologies. Missing evidence proves neither silence nor no effect.

Only `presence_retry_proof` permits regeneration: first-round temporary refusal, every route engine-confirmed `not_started` and ledger-released, no response/tool/handoff, and a dated reset. After reset the conversation gate writes `presence_retry_next`, a new physical ID under the original event; other refusals remain retained. A live turn's shared fallback/continuation (§6) keeps earlier effects, unknown cost, controls and its conversation through recovery or retained refusal, never replaying the event.

`/presence/work` separates queried `work_ref`, producer `task_id`, canonical `output_ref` and actual `child_work_ref`. Original/child/continuation outputs, including selected failed terminals, deduplicate by output identity, never text or queried work. Legacy gaps stay gaps (`test_presence_connector_contract.py`).

`presence_continuation.py` parks only for the author's left review (commit/change/result, `review_pause`) or required private Main question. It grants no generic sleep, detach, owner Pause or budget-pause callback. With tool, process and service custody idle, it records `open_turns` and a source-bound write-once initial envelope on the RUNNING task, reads them back, publishes the envelope, then lends conversation and active slot. Otherwise it waits holding custody. Reentry reacquires both in admission order before any model/tool/forced call and appends `[PRESENCE CONVERSATION RESUMED]` facts. Hard stops use the zero-call rail; rounds and wallet persist. Bound question waits resume without inventing consent; durable terminal rows reconcile questions and waits, including cancellations, while unknown attempts remain unconfirmed. Wait-ended events address the question's publication room.

Only `continuation_version: 1` takes the initial envelope; others await terminal. Reviews never publish; released selections never resend. Lost authors stay interrupted until an explicit new event starts a new author from retained facts (CREATING_SKILLS “Presence continuation”).

Reentry retains exact rows and gaps in immutable `presence_reentry` artifacts, read through existing task scope with `get_task_result(task_id, presence_reentry_sha256, …)` and `presence_reentry_offset`. It reads only the producer's conversation from `state/dialog.sqlite` within frozen bounds. Legacy cursors use the import ledger; new snapshots bind the end to a retained row identity. Inode/mtime-only snapshots report `legacy_source_identity_unavailable`, keeping their text; import gaps remain explicit (§6). `presence_observations.py` accepts transport-queue snapshots in `event.conversation.transport_queue` or authenticated work POSTs: dated observations, never inbox certainty, admission or delivery proof; absent means unknown.

Entry/receipt identity is `presence_bindings.conversation_key` (empty thread `0`). Durable `first_lent_at` anchors parks/termination; returning authors update their own `open_turns` entry without replacing newer pointers. Outcomes: `message`, `silent`, `tool_delivered`, `deferred` (requires admission; orphaned children replay silent). `peer_roster.independent_message_target` admits `forward_to_worker` to source-bound RUNNING turns as peer context, never owner authority. Proactive speech uses connector tools.

`places.py` owns atomic revisioned `state/places.json` for `gateway/places_api.py` and `configure_presence`. Connect creates Silent; repeat Connect keeps choices; low-level/migration defaults stay Active. Only owner doors/APIs confirm accounts or activate; consciousness may set Silent/Paused. Changed records take the next document revision; edit/disconnect refuse stale revisions with current summary or null. Migration copies bindings/instructions/topics/model/folder once, retaining files and route identities. Connector updates never replace choices.

`place_projection.place_view/places_view` owns PlaceSummary: label, icon, readiness, source/settings, facts/labels, revision, rooms, nullable spend, identity/owner/can_confirm and consciousness safety_mode. `extension_contributions` validates status with `places.validate_presence_identity`; `gateway/places_api.read_place_status` reuses reviewed route dispatch. Status/launch keep their brief stored view; display money may be stale, admission strict. Connect source lists distinguish absent/nonempty/empty/unavailable; null accounts are not wildcards, broad/narrow places coexist (CLIENT_CONTRACT “Places”).

Contribution `facts` declares core kinds (optional labels) and labelled `signal.<slug>`, `wakes` defaults. `/identity` advertises `presence_wake_signals: 1` and `presence_identity: 1`. Intake and new signal choices require the live declaration; saved choices stay removable while off. Connector settings own signal logic; bot gating/OR semantics stay unchanged (CREATING_SKILLS).

`ouroboros/gateway/host_service_places.py` captures source events/attachments before admission. Paused, Off/Panic and unmatched events settle heard/silent; exhausted or unknown allowance requests retry. `conversation_lease.py` owns process/file locks, lending and reacquisition. Only an accepting local author with a held conversation lease receives `place_event` context-only mail, under its final-drain admission lock; a closed, ended or remote author leaves ordinary admission eligible. Accepted final-drain context earns a round, never owner authority. Stop finds remote lent authors by stack-lifetime locks; reentry checks `supervisor.consciousness_carriers.autonomous_work_enabled` before reacquiring, ending on the zero-call rail if disabled. Focus keeps consciousness provenance/autonomy and a root cost ceiling; no new capability ceiling, legacy ceilings stay decodable.

`presence_context.py` appends FOCUS after the shared prefix: actor/wake facts, notes, work, allowance, roots, folder and full knowledge topics. Event identity wins over status; owner flags derive through the account-scoped helper. `actor.authenticated: false` prevents owner confirmation/Safety occasion/root promotion; absent preserves platform behavior. Voice facts feed FOCUS, `consciousness_view.places_text`, Safety (`place_guard.call_place_facts`) and focus wake rows (`as`). `finish_task` selects speech/silence. `place_reply.py` checks state/Safety before automatic speech, including promoted roots. Flags return to the mind; Silent/Paused/disconnected/Advises holds create one System row per subject. Forced finals cannot bypass flags. Cached turns/envelopes/polls recheck state without generation or another Safety call; silent answers retain output identity and custody. Late receipts remain evidence with warnings.

Per-turn receipt negotiation: CREATING_SKILLS “Reporting actual Presence delivery”. `presence_delivery.py` writes authenticated `/presence/delivery` observations: mode 1 records provider-receipted speech, mode 0 unconfirmed authorship. Receipts prove writing, not reading, and never finalize tasks; failures/uncertainty are System facts. Identical readable reports deduplicate; conflicts refuse. Malformed history gives `history_coverage=gapped`; `duplicate=false` then means no readable match. Outboxes own report backoff; report failure neither resends nor blocks delivery. Client-id lookup in `dialog.sqlite` survives restart and refuses unknown import coverage.

### Companion processes

Reviewed manifest descriptors enter host-supervised durable custody: reconcile after lifecycle changes/restart; stop on disable, unload or panic. Workers adopt the server's live set from `state/extension_generation.json` at task start or a dispatch miss, without waiting for pool respawn. Worker changes request reconciliation through `state/extension_reconcile/`, never spawn server children. Each result names its observing process. Server health is authoritative; worker evidence qualifies it, and failed handoff cannot advance `last_known_good`. Exhausted restart budgets retain their terminal reason until a successful start. The reviewed payload is the companion's cwd; edits stale review before reload. `state/extension_companions.json` projects live state (§13).

### Chat-id delivery

Each message has exactly ONE destination. Chat IDs are values; absence is `None` (§11.1 `chat_id_policy`). `HIDDEN_CHAT_ID` (0) is the hidden destination for Skill Review and unbound headless work, with no browser reader. `message_bus.notification_chat_route` decides where a notice goes; a `chat_id=0` history query coerces to Main, excluding chat-0 rows. A lineage binding or the task's admitted Project chat brings them to a Project; negative A2A ids never enter human streams. An exhausted terminal outbox notice skips chat 0 (no reader) while the durable incident and saved message remain; only positive same-id, same-destination evidence (`terminal_delivery`) suppresses it, never a bare delivered id or a missing ACK. Memory/consolidation provenance follows the same value/`None` policy: a per-window registry snapshot names Main and the current Projects by stable chat id, missing or ambiguous values stay explicit (never Main), and a presence room is named only by transport facts that re-derive its chat id; these labels are read-only attribution and alter no routing, visibility or delivery.

`place_intake.py` decides attention; `place_arrivals.py` owns heard decisions, deferred sources and room/activity indexes. `loop_completion_schema.py` selects completion, preserving live legacy registries; `tool_effects.py`/`place_guard.py` own effects/targets (§13).

Heard-only events create no task/context blob; the room row keeps identity/reason (`paused`, `off`, `no_wake_match`, current-author handoff). Later On never reconsiders them. Focus/heard settlement share the intake lock and preserve custody. Source rows stay immutable; `dialogue_store` derives deferred pointers from dedup records; `chat_chain.source_row_id` preserves identity.

`places.place_room_index` reads latest arrivals and nonterminal focus counts through indexes, without historical walks or per-arrival document loads. Unknown task-store counts stay null. Only the owner's rooms endpoint requests arrival details, decoded after the transaction; polls stay index-only. Discovery may miss legacy/outgoing-only rooms; import/gap flags describe the store, not provider completeness. Indexes build once from source rows. `ouroboros/gateway/place_history.py` projects recorded delivery/heard facts, exact-task focus starts and current owner confirmation (CLIENT_CONTRACT “Places”). `account_candidates` suggests up to 20 nonbots from the newest 50 arrivals, without identity confirmation or another actor list. Migration imports valid neighbors, records bad bindings in `migration.problems` and publishes one marker; `/api/places` exposes `migration_problems`.

For an opaque outbox mutation (empty conversation id), `GET /presence/place` reports any Silent/Paused place owned by that authenticated connector/provider/account, including broad and migrated wildcard accounts. An optional `thread_id` resolves a topic-specific place; omission keeps the room lookup. Declared tool destinations match account, conversation and thread as separate facts, each recipient checked independently. Retained-work GET/POST may omit `binding_id`; authentication checks the retained task's connector, never the ref alone. POST accepts exactly `transport_queue` plus an optional `binding_id`; legacy binding ids remain checked.
